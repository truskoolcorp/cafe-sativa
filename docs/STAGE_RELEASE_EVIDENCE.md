# Stage canary evidence handoff

`reconcileStageRelease` evaluates normalized read-only evidence for one exact
program occurrence. It does not collect or store evidence, release a replay,
send a post, grant approval, or qualify the seven-day automation gate.

| Input | Supply only after |
| --- | --- |
| Lobby | The canonical production URL shows the correct program and kickoff before the event. |
| Playback | The production player is observed advancing through the approved cut during the actual slot; keep media QA and rights evidence with the run record. |
| Moderation | Cross-account event chat, a handled audience question, and an audited report/removal are observed in the production slot. A role grant, a rehearsal, or a host name alone is not this receipt. |
| Destination | The exact approved track, artist, or product destination is independently opened and verified against the program, and the intended on-page CTA lands there. |
| Replay | After the slot, the released replay passes entitled playback and non-entitled denial checks. The archive landing page alone is not proof. |
| Facebook / Instagram | Record each provider's result for the exact approved Metricool post under Café Sativa brand 7605217. On success, bind the platform-issued identifier and permalink, then independently confirm the post on the intended account. |

Use UTC epoch milliseconds. Bind every website receipt to the canonical event
URL and a unique occurrence ID; never normalize a fixture into a production
receipt. Evidence IDs reference retained observations, not credentials,
signed media URLs, audience messages, or customer data. For a social
publication receipt, the public readback is a separate check at or after the
provider's recorded observation. Store the exact approved caption, media hash,
account binding, settings and promotion deadline in the release record.

A missing promotion binding stays held. A scheduled or unreturned receipt
within the grace window stays pending; an overdue or contradictory one needs
reconciliation. Do not infer failure from elapsed time, nor resend on ambiguity.
If a provider confirms one network failed, preserve the sibling's receipt and
use the existing publication gate for any network-specific repair.
