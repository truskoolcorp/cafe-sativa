# Café Metricool adapter: dormant proposal

No route, environment flag, connection write, provider call or publishing integration is added. Existing Tru Skool v1 snapshots and authorization remain untouched. Café v1 schedules are a separate protocol, not cast into the old hard-coded Keith/Tru Skool schema.

Target: Metricool brand7605217, Facebook105363501666032, Instagramcafesativainc. A fresh provider brand read must match user identity, both destination bindings and timezone. Per-platform payload uses the approved caption and relevant hashtag list; Facebook Reel title and Instagram collaborator invitations remain separate fields. Cross-platform handle inference is forbidden. No persona has a built-in collaborator grant: the server must supply a verified exact persona/network/handle/evidence allowlist from owner intent. Scheduling is not publication, and collaborator invitation requested is not acceptance.

The full content approval digest, metadata, destination, collaborator evidence and schedule are hashed into the immutable dispatch digest. Required injected authorization must revalidate final canonical content, voice, rights, watermark QA, account/actor and publication scope. Existing known-external receipt exclusions must be applied there. Relevant hashtags are an editorial requirement reviewed with the snapshot, not inferred from tag popularity.

Required durable-store contract: atomically compare exact approval and claim UNIQUE(planId), UNIQUE(destination/time key) and UNIQUE(media/destination key) together. Same media on the same destination is held across rescheduling/copying, even with a different approval; any intentional repost requires a separate reviewed reconciliation, not bypass. Never reclaim or expire. Immediately persist lossless provider ID+UUID by claim-token CAS, before readback. Final scheduled receipt requires exact platform metadata and hosted byte hash verification. Uncertainty consumes the claim, preserving provider identity for reconciliation, never automatic create/update/retry. Same destination/time collision is blocked even if caption differs. Provider scheduled-list absence does not prove publication or safe retry.

Before runtime integration: independently review actual provider fields, install and PG17-test a new durable snapshot/receipt store (old v1 SQL is not compatible), connect existing authorized bearer session without widening credentials, wire exact final-content/watermark/known-external checks, test finite authorized schedules, and obtain exact-head CI. No deployment during the private canary freeze. This module alone does not make recurring delivery live.
