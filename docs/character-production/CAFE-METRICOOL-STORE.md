# Dormant Café scheduling store

This proposal is not deployed and adds no credentials, runtime grants, route, automatic approval writer or publishing enablement. Apply only under a separately reviewed dedicated owner after existing schema/trigger compatibility is verified. The owner-only approvals table starts empty. A provider connection is not an approval.

Each approval must be created by a reviewed authority workflow, not copied from nullable legacy timestamps. It binds the complete sorted schedule digest, both computed reservation keys, exact current source-state JSON, approver and finite expiry. No writer is provided here. The existing final-authorizer injection remains mandatory for fresh canonical rights, exact private media bytes, watermark evidence, collaborator identity and live provider account mapping. The store does not claim to verify external services.

Claim locks the parent draft (the existing source mutation guards serialize on that row), locks its approval, validates the complete source state, final timestamps and nine exact-video QA checks, then atomically inserts all three unique reservations. Across plan IDs, either destination+time or destination+media collision refuses the entire claim. The new source guards also freeze draft, plan and QA mutations after any Café attempt using the same parent lock; all intended platform plans must therefore exist before dispatch. Existing legacy guards are not removed. No expiry, delete, reclaim or automatic retry exists. Unknown outcomes remain permanently held.

Provider ID and UUID are recorded before readback; unknown status never clears them. Exact scheduled receipt compares every field to the approved schedule and stored identities. Scheduled means provider scheduling readback, not publication or collaborator acceptance. After a committed receipt is reported uncertain, a downgrade is refused. Receipt persistence remains possible after approval revocation because it records an already attempted external action, not new authority.

Runtime requires current known-external receipts (including subsequent clean replacement receipts), an independently reviewed authority workflow, exact source triggers, safe role grants, and verified Facebook title API contract. None is silently bypassed by this store. No production activation is authorized by passing synthetic or PostgreSQL tests.
