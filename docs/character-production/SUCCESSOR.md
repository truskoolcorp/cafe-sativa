# Terminal-confirmed successor (dormant source)

This is not production activation or evidence of a completed automated run.

The no-argument `createCafeSuccessorOperation` makes one finite call to
`character_production_successor_context`. A separately reviewed trusted entry
may invoke it, drain `whenSettled`, and stop that tick. Later ticks use the
existing preparation, original-speech recovery, first-admission and selected
production paths against the retained new occurrence. No public caller supplies
an actor, lane, date, policy, script, quote or receipt.

The SQL requires the current original draft's actual Facebook AND Instagram
publication receipt predicate before retiring its enrollment. A scheduled post,
missing post, failed/unknown response or only one published destination never
permits advance. Before terminal proof the old artifact/reconciliation path is
left intact. The successor has new occurrence/enrollment/text identities, not a
replay of existing introductions. One retained edge per standing scope and
Dallas calendar day prevents catch-up bursts. The same text budget and video
policy cap/period remain authoritative; no ledger is reset.

`CS_CHARACTER_SUCCESSOR_ENABLED` defaults off. The runtime has one-shot semantics,
a finite inherited abort signal, disabled/signal checks at native dispatch after
SDK preparation, no retries, and drains the original transport. Unknown results
are held. A later invocation reads durable state; it does not synthesize again.
A `successor_prepared` result means only a durable next occurrence was created:
it explicitly does not mean generated or published.

## Required separately reviewed authority

No installation, grants, owner rows, routes or cron activation are performed here.
The source proposal needs restricted-owner installation; service runtime would
need the single successor RPC capability. The character-production owner also
needs the narrow `public.cs_cafe_publication_terminal(uuid)` EXECUTE capability
from the separate Café publication owner. That is new cross-owner access to a
boolean proof, not broad publication-table access. Existing service-role
inheritance must be disclosed and verified before live grant. Owner-provisioned
standing configuration is immutable except one-way disable and binds the root
lane/configuration, recorded owner authorization and expiration. It is not a new
per-post approval requirement within the authorized scope.

The existing fresh-speech standing scope may authorize a new daily script only
while that original scope remains current. This proposal never creates a speech
scope or extends its expiration. Original speech receipts remain recoverable
read-only; an unknown original claim is never retried/reset.

## Remaining prerequisite

The successor reuses only the exact reviewed original quote while still current.
It holds when quote evidence is stale. No trusted recurring quote-refresh source
has been installed by this change; indefinite recurrence is therefore NOT
claimed. Actual current canon, media, owner policy, quota/budget and all later QA
and delivery checks still apply. No new provider calls, charges, automatic
top-ups or third-party watermarks are permitted by this source.
