# Private technical receipts (dormant)

This sidecar records bounded native codec observations, not human review or publishing authority. The existing nine-check public QA gate remains unchanged. Integrity and actual duration can pass; canonical speech, likeness, lip sync, visual text, rights, brand safety and third-party watermark checks remain `needs_review`. A matching source PCM hash does not prove perceptual quality.

The evaluator fingerprints the actual ffmpeg and ffprobe executables before and after execution and records their native version output. Version 1 identifies this assessor contract, not a fabricated build commit. Trusted selected-token, immutable snapshot, original speech/audio receipt, draft revision and video hashes bind the observation. The writer accepts no caller reviewer/owner identity. It is owner-only pending separately reviewed narrow access installation; neither SQL proposal nor default-off code enables production.

The runtime first reads an existing exact receipt. If none exists it may repeat harmless private local decode. Only after successful evaluation does it consume one durable mutation claim, immediately before the one persistence call. A lost claim response or unknown write result permits read-only receipt reconciliation, not another write or claim reset. Failure before the claim does not strand local evaluation. A consumed claim without a receipt is an unknown mutation state requiring separately reviewed recovery. Original-token reads intentionally remain possible after expiry/revocation solely for exact retained evidence; they confer no current write or publish authority.

Both `CS_CHARACTER_TECHNICAL_QA_ENABLED` and `CS_CHARACTER_TECHNICAL_RECEIPTS_ENABLED` must remain true at native receipt-RPC dispatch. Defaults are off; no grants, activation, paid review or provider calls are included. Actual PostgreSQL 17 and full strict TypeScript CI must pass before dormant merge. Production binary packaging, memory/CPU isolation and genuine perceptual review remain separate readiness requirements.
