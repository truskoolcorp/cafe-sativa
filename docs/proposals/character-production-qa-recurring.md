## Separate inert installer candidate

`character-production-qa-recurring-install.sql` is generated by the pinned `prepare-qa-recurring-install.py`. It creates **no binding rows**. Only the two queue/materialize RPCs receive existing backend `service_role` execute. No generator/broker grant, credentials, planner creation, flags or recurring activation is included.

The installer adds a fixed source-owner boolean helper (`draft_unplanned(UUID)`) callable only by the existing production owner. It exposes no source rows or private ledger state. The generated overlay checks this helper only after the binding joins and, for materialization/replay, after the draft row is locked. Drafts with **any delivery plan** are excluded, avoiding frozen-plan queue starvation without broad private-ledger reads. An immediate validated plan-to-draft FK is a precondition; it serializes concurrent plan insertion against the materializer's draft lock. Planners must not attach delivery plans until QA has completed. This helper is not a new publisher or a replacement for existing source-freeze triggers.

The original non-superuser installer must own the source draft and delivery-plan tables (production evidence: postgres; fixture identity: provision_installer). All prior ledger/source rows, ACLs, memberships, policies, triggers and functions are snapshotted and checked unchanged. Temporary self-SET, public CREATE, draft REFERENCES(id), and conditional private namespace USAGE are restored. The only persistent changes are the new empty binding table, its guard, two RPCs, owner-only boolean helper and two prebinding policies with fixed reviewed grants.
