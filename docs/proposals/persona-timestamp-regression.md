# Actual PostgreSQL timestamp integration regression

Run `python tests/sql/run-persona-timestamp-single.py /path/to/pg17/bin /path/to/pg17/share /fresh/evidence/directory` from the runtime sibling. The runner creates a disposable local cluster through the existing isolated single-user fixture runner. It never opens sockets or starts a network listener.

The regression uses the unchanged SQL proposals and real TypeScript source reader, review builder and final snapshot builder. Storage bytes, GLYPH and provider destination inputs are local mocks; draft, plan, QA, generation and gate rows come from actual PostgreSQL exports. A genuine voice RPC creates its stamp with SQL clock_timestamp(). The test requires nonzero submillisecond precision, round-trips exact SQL rows through readCharacterPromoSources, and submits the resulting model.expected to actual video and publication RPCs. It also builds a final snapshot from the actual reader and requires the real SQL final approval RPC to accept it. No production approval or provider action occurs.

A negative control deliberately truncates the reader's next-gate expected revision and voice stamp to milliseconds and asserts that strict SQL CAS returns null. The precision-preserving payload must succeed immediately afterward. This demonstrates the original failure and the fix across SQL/JavaScript, rather than checking only a timestamp helper.

Evidence is written to the supplied directory, including complete synthetic exported rows, reader payloads, standalone SQL logs and timestamp-results.json. If the wall clock happens to produce exactly millisecond-aligned voice evidence, a fixture-only subtransaction rolls that voice call back and retries, bounded to ten genuine RPC calls. Stored timestamp digits are never synthesized or altered; the test fails if no genuine submillisecond sample is obtained.

Hosted wiring: `.github/workflows/persona-runtime-proposal.yml` now includes a third independent fresh PG17/Node job, installs dependencies with `npm ci --ignore-scripts`, and runs `python tests/sql/run-persona-timestamp-single.py --hosted-ci .persona-timestamp-ci`. The guarded hosted transport requires CI=true, PGHOST=127.0.0.1 and PGUSER=postgres, creates its own disposable database and uses the same actual TS reader, negative control, next-gate and final SQL checks. Source/helper/model/dependency and fixture paths are included in PR filters. Local real single-user execution passed again after adding this transport, and YAML/path/Python syntax checks passed. The hosted transport and job were not invoked or published; no local socket or network workaround was attempted.
