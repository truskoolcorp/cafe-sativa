# Dormant resource-safe public readiness candidate

LOCAL ONLY. Runtime remains null/unconfigured and returns generic 503 with zero reads. No real private pin or public-artifact approval is present. This patch does not enable a route, deploy, change database privileges, post chat, or establish approval. The runtime constructs one fixed server factory with literal null approval. Construction and disabled requests read no environment or credentials and perform no network I/O. The route forwards Request.signal only, never request configuration. Tests use synthetic canon and approval only.

## Resource contract

The trusted composition factory fixes GLYPH to the existing server helper and pins the verified Supabase project origin, rejects any other configured origin before I/O, and fixes the event read to the anonymous public `my_events_v` listing fields. Optional AbortSignal support leaves other GLYPH callers' existing behavior unchanged. No cookies, user session, service-role client or admin table is used. Runtime configuration is checked before either read; missing approval or missing/invalid runtime configuration causes zero network I/O. Factories and dependencies are trusted server code, never request input. No request-controlled URL, pins, source selection or caller freshness assertion is accepted.

Per service instance: one physical flight, at most 16 admitted waiters, two parallel source reads, a 1,500 ms deadline covering headers, bodies and evidence projection, a minimum of 5 seconds between reads, a 10-second backoff on failure. Monotonic elapsed time is checked before and after projection as well as a timer, so overdue work cannot succeed merely by starving the timer. JavaScript cannot hard-preempt blocking native/CPU work: process/container isolation and hosting deadlines remain required. Body parsing accepts at most 262,144 bytes, 1,024 read iterations, 10,000 JSON nodes and depth 32. It rejects duplicate decoded JSON keys, invalid UTF-8, wrong MIME, redirects and malformed/oversized bodies; yields every 32 chunks so empty chunks cannot starve cancellation. Fetch receives the same signal as streaming body consumption. Cancellation settlement is awaited; a dependency that ignores abort retains the sole flight slot until it actually settles. Late work cannot publish success or start another flight. No scheduled/detached refresh work is created. Unavoidable non-cooperative work may remain after request cancellation, quarantined rather than multiplied.

Each waiter may cancel independently. Only when the last waiter leaves is the shared upstream work canceled. Other callers cannot be directly canceled by one departing waiter. Server deadline still closes the entire flight. The route passes the actual Request.signal through the disabled runtime singleton; no URL, headers, cookies or body are read.

Only serialized public success projection is cached, with its original start/expiry and equivalent monotonic age/expiry bounds (a frozen wall clock cannot prolong cache). Cache hits deserialize a fresh copy and never restamp timestamps. Demand at 30 seconds original observation age performs a fresh read before the 60-second TTL; no background polling, stale-while-revalidate or stale-on-error exists. Pending renewal/failure/revocation drops the previous cache. Cache expiry remains the earlier of original evidence TTL or approval end. Source revocation is observable only on the next demand refresh (normally at 30 seconds), not instantaneously. Finite wall-clock regression or a clock exception permanently poisons the service instance, clearing success. Approval config is an immutable construction snapshot; replacing or disabling the instance is required to revoke/change that approval. Caller object mutation is not revocation.

Registry `verifiedAt` is observation completion, not profile creation or fallback-free provenance; the original timestamp must lie within the fresh request interval and is never restamped.
- Verify production anonymous event-view grants/RLS and existing environment configuration using an authorized future live check. This local patch proves code structure, not deployed permissions or credential role correctness. Existing production-only GLYPH credentials are not copied into preview.
- Measure real header/body/event latency against the 1,500 ms server budget and the consumer’s 2-second deadline. Availability under this budget is UNVERIFIED; slow live dependencies can correctly return unavailable. This patch does not claim solved availability.
- Review the deployed process/module lifecycle to ensure exactly one long-lived service instance per process. Per-process singleflight/rate limits are NOT global protection: multiple instances, cold starts and regions multiply requests. An authorized hosting/ingress rate limit, aggregate upstream concurrency/budget and maximum instance policy are still required. No WAF configuration or global protection was invented or activated here.
- Preserve the now-wired request signal and no-store public headers during activation, and verify no source URLs, canon, secret headers or pins are exposed. The separate consumer/operator writer remains disabled and unchanged.

No live network check, credential retrieval, database write, privilege change, deployment, push or public posting was performed for this artifact.
